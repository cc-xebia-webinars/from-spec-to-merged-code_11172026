## Webinar Overview

### Description

The first session covered the shift from autocomplete to autonomous agents and the mental models needed to work with them. Since then the tools have changed shape: agents now spawn sub-agents, run unattended in the cloud, review each other's pull requests, and bill by the token. The bottleneck has moved from generating code to keeping agents grounded, verifiable, and affordable. This demo-driven session shows the workflows that have emerged in 2026 for running multiple AI coding agents as a coordinated engineering system. After a short framing of what changed and why spec-driven development is now the anchor practice, we spend the majority of the session live in the tools, taking a feature from spec to verified, reviewed, merged code.

### Agenda

-   What changed in 2026: nested sub-agents, parallel fleet execution, cloud-hosted coding agents, agentic code review, million-token context windows, and token-based billing
-   Spec-driven development: writing an executable spec and having agents plan against it before any code is written
-   Agent teams in action: coordinator, implementor, and verifier roles with scoped permissions and per-agent cost tracking
-   Context engineering: instruction files, reusable skills, and a live MCP server feeding every agent the same ground truth
-   Autonomous loops: test-fix-repeat cycles running locally while a cloud agent works an issue to a draft PR
-   Adversarial verification: a second agent catching scope creep and drift that tests cannot
-   Closing the loop: agentic code review, auto-generated fix PRs, and the human merge decision
-   Cost and governance takeaways: what the whole run cost, and where to draw the autonomy line
